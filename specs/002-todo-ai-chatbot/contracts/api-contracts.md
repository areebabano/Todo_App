# API Contracts: Todo AI Chatbot (Phase III)

**Branch**: `002-todo-ai-chatbot` | **Date**: 2026-02-13

## Overview

Phase III adds two new API surface areas:

1. **ChatKit Protocol Endpoints** — Handled by ChatKit Python SDK server (thread management, message streaming)
2. **MCP Tool Definitions** — Exposed via FastMCP server for the AI agent to invoke

Existing Phase II endpoints (`/api/v1/tasks/*`, `/api/v1/auth/*`) remain unchanged.

---

## 1. ChatKit Server Endpoints

These endpoints are auto-generated by the ChatKit Python SDK's `ChatKitServer` when mounted on FastAPI. The ChatKit frontend communicates with these automatically.

### Base Path: `/api/v1/chat`

| Method | Path | Description | Auth Required |
|---|---|---|---|
| POST | `/api/v1/chat/threads` | Create a new conversation thread | Yes |
| GET | `/api/v1/chat/threads` | List user's conversation threads | Yes |
| GET | `/api/v1/chat/threads/{thread_id}` | Get thread with message history | Yes |
| DELETE | `/api/v1/chat/threads/{thread_id}` | Delete a conversation thread | Yes |
| POST | `/api/v1/chat/threads/{thread_id}/messages` | Send a message and receive streaming response | Yes |

**Note**: The exact endpoint structure follows ChatKit Python SDK conventions. The paths above represent the logical operations; actual paths may be determined by the SDK's routing.

### Thread Create

**Request**:
```
POST /api/v1/chat/threads
Authorization: Bearer <session_token> (via cookie)
```

**Response** (201):
```json
{
  "id": "uuid",
  "title": null,
  "is_active": true,
  "created_at": "2026-02-13T10:00:00Z"
}
```

### Thread List

**Request**:
```
GET /api/v1/chat/threads
Authorization: Bearer <session_token> (via cookie)
```

**Response** (200):
```json
{
  "threads": [
    {
      "id": "uuid",
      "title": "Task management conversation",
      "is_active": true,
      "created_at": "2026-02-13T10:00:00Z",
      "updated_at": "2026-02-13T10:05:00Z"
    }
  ]
}
```

### Send Message (Streaming)

**Request**:
```
POST /api/v1/chat/threads/{thread_id}/messages
Content-Type: application/json
Authorization: Bearer <session_token> (via cookie)

{
  "content": "Add a task to buy groceries"
}
```

**Response** (200, streaming):
```
Content-Type: text/event-stream

data: {"type": "text_delta", "content": "I"}
data: {"type": "text_delta", "content": "'ve"}
data: {"type": "text_delta", "content": " created"}
...
data: {"type": "tool_call", "name": "create_task", "arguments": {"title": "Buy groceries"}}
data: {"type": "tool_result", "name": "create_task", "result": "Task created successfully"}
data: {"type": "text_delta", "content": "Done! I've created a task called \"Buy groceries\"."}
data: {"type": "done"}
```

### Thread History

**Request**:
```
GET /api/v1/chat/threads/{thread_id}
Authorization: Bearer <session_token> (via cookie)
```

**Response** (200):
```json
{
  "id": "uuid",
  "title": "Task management conversation",
  "is_active": true,
  "messages": [
    {
      "id": "uuid",
      "role": "user",
      "content": "Add a task to buy groceries",

    },
    {
      "id": "uuid",
      "role": "assistant",
      "content": "Done! I've created a task called \"Buy groceries\".",
      "tool_calls": [
        {
          "name": "create_task",
          "arguments": {"title": "Buy groceries"},
          "result_summary": "Task created"
        }
      ],
      "created_at": "2026-02-13T10:00:02Z"
    }

```

## 2. MCP Tool Definitions

These tools are exposed by the FastMCP server and consumed by the OpenAI Agents SDK agent. They are NOT directly called by the frontend. Each tool is stateless and receives all required context as parameters.

### Base Path: `/mcp` (internal, Streamable HTTP)

### Tool: `create_task`

Creates a new todo task for the specified user.

| Parameter | Type | Required | Description |
|---|---|---|---|
| owner_user_id | string | Yes | The authenticated user's ID |
| title | string | Yes | Task title (1-100 characters) |
| description | string | No | Task description (max 500 characters) |

**Returns**: JSON object with created task details (id, title, description, is_completed, created_at)

---

### Tool: `list_tasks`

Lists todo tasks for the specified user, optionally filtered by completion status.

| Parameter | Type | Required | Description |
|---|---|---|---|
| owner_user_id | string | Yes | The authenticated user's ID |
| status_filter | string | No | Filter: "all" (default), "active", "completed" |
| limit | integer | No | Max number of tasks to return (default: 10) |
| offset | integer | No | Number of tasks to skip for pagination (default: 0) |

**Returns**: JSON array of task objects with count metadata

---

### Tool: `update_task`

Updates an existing task's title and/or description.

| Parameter | Type | Required | Description |
|---|---|---|---|
| owner_user_id | string | Yes | The authenticated user's ID |
| task_id | string | Yes | UUID of the task to update |
| title | string | No | New title (1-100 characters) |
| description | string | No | New description (max 500 characters) |

**Returns**: JSON object with updated task details

**Error**: Returns error message if task not found or not owned by user

---

### Tool: `delete_task`

Permanently deletes a task.

| Parameter | Type | Required | Description |
|---|---|---|---|
| owner_user_id | string | Yes | The authenticated user's ID |
| task_id | string | Yes | UUID of the task to delete |

**Returns**: Confirmation message with deleted task title

**Error**: Returns error message if task not found or not owned by user

---

### Tool: `complete_task`

Marks a task as completed.

| Parameter | Type | Required | Description |
|---|---|---|---|
| owner_user_id | string | Yes | The authenticated user's ID |
| task_id | string | Yes | UUID of the task to complete |

**Returns**: Confirmation message with task title and completion timestamp

**Error**: Returns error message if task not found, not owned by user, or already completed

---

### Tool: `incomplete_task`

Marks a completed task as incomplete.

| Parameter | Type | Required | Description |
|---|---|---|---|
| owner_user_id | string | Yes | The authenticated user's ID |
| task_id | string | Yes | UUID of the task to mark incomplete |

**Returns**: Confirmation message with task title

**Error**: Returns error message if task not found, not owned by user, or already incomplete

## 3. Error Response Contract

All endpoints follow the existing Phase II error format:

```json
{
  "detail": "Human-readable error message"
}
```

| Status Code | Meaning |
|---|---|
| 400 | Bad request (validation error) |
| 401 | Not authenticated |
| 403 | Not authorized (resource not owned by user) |
| 404 | Resource not found |
| 422 | Validation error (input format) |
| 429 | Rate limited |
| 500 | Internal server error |
| 503 | AI service unavailable |

---

## 4. Authentication Contract

All ChatKit and MCP endpoints use the existing Better Auth session authentication:

- Session token passed via `better-auth.session_token` httpOnly cookie
- Backend extracts and verifies token via Better Auth session table lookup
- `owner_user_id` extracted from verified session
- No changes to the existing authentication flow
